# ADR-0005: 項目の図版は、ソフトのロゴではなく架空の生き物として描く

- 状態: 採用

## 文脈

サイトは、Vim の操作で使えるソフトを図鑑の生き物に見立てて紹介する。項目に図版があれば図鑑らしくなる。ソフトを見た目で表すものとしては、まずロゴがある。

ロゴの多くは商標である。著作権が CC ライセンスで許諾されていても、それは商標の許諾ではない。VS Code や JetBrains の製品のように、商標のポリシーでロゴの改変を禁じているソフトもある。図鑑の画風に合わせてロゴを描き直せば、ロゴの改変にあたる。

## 決定

- 図版には、ソフトのロゴも、ロゴを描き直したものも使わない。
- 各項目の図版は、そのソフトの性質と種別（ADR-0002）から想像した架空の生き物として、新しく描く。
  - たとえば、ブラウザの入力欄に Neovim を寄生させる Firenvim は、ブラウザに取りつく火トカゲとして描く。
- 図版は、項目のページバンドルに `plate.svg` か `plate.png` / `plate.jpg` として置く。
  - SVG はページに埋め込み、テーマのインクの色とかすれで描く。
  - ラスター画像は、テーマが図鑑の色調に揃える。
- 図版のない項目には、テーマの「未確認種 ― 目撃情報求む」の図版を出す。

## 理由

- 商標の改変を避けられる。ロゴの持ち主ごとに、ポリシーを確かめる必要もない。
- 架空の生き物は、サイトの見立て（図鑑）にそのまま合う。
- 図版のない項目を、図鑑の見立てのまま「まだ図版がない」と示せる。

## 採らなかった案

- CC ライセンスのロゴだけを描き直して載せる：著作権の許諾は商標の許諾ではなく、改変を禁じる商標ポリシーにも当たりうる。
- ロゴをそのまま載せる：図鑑の画風から浮く。改変しなくても、商標の使い方のポリシーを項目ごとに確かめる必要が残る。
- 図版を載せない：図鑑らしさの大きな部分を欠く。

## 結果

- 図版は、ソフトの性質を読み取って描く手間がかかる。描き終わるまでのあいだ、多くの項目は「目撃情報求む」の図版を出す。
- 図版を描くたびに、生き物の見立てを短いキャプションに書く。
