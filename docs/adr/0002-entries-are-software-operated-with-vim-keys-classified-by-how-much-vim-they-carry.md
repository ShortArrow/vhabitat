# ADR-0002: 載せるのは Vim の操作で使えるソフトだけとし、Vim をどこまで持つかで種別を付ける

- 状態: 採用

## 文脈

サイトは、Vim の操作で使えるソフトを図鑑のように紹介する。各ページには載せる基準が書かれていない。Playgrounds のページには、Vim の操作を持たない playground も「not infected with vim」の節に並んでいる。

ページは提供形態で分かれている。ブラウザ拡張、IDE、playground、単体ソフトの 4 つである。同じページの中でも、Vim との関係はソフトごとに違う。Neovim を中で動かすもの、Vim の操作を自前で再現するもの、独自の操作に Vim 由来のキーを使うものが混ざっている。

## 決定

- 載せるのは、Vim の操作で使えるソフトだけとする。Vim の操作とは、モードの切り替えや hjkl での移動、オペレーターとモーションの組み合わせなどのことである。Vim の操作を持たないソフトは載せない。
- 各項目には、次の種別を 1 つ付ける。

| 種別 | 定義 | 例 |
|---|---|---|
| 原種 | Vim の系譜そのもの | vi、Vim、Neovim |
| 寄生 | Vim か Neovim の本体を動かし、ほかのアプリの画面の中で編集させる | vscode-neovim、Firenvim |
| 共生 | ほかのアプリと、別の窓で動く Vim か Neovim の本体とのあいだで、テキストを受け渡す | GhostText、Open In Neovim |
| 擬態 | Vim を使わずに、Vim の操作を再現することを目指す | VSCodeVim、IdeaVim、Vimium-C |
| 近縁種 | 独自の操作体系の一部に、Vim 由来のキーを使う | lazygit、bottom |

- ページは、今の提供形態の分け方のままとする。種別は、ページではなく項目ごとの欄として持つ。

## 理由

- 読者が知りたいのは、そのソフトで Vim の操作がどこまで通じるかである。
  - 寄生と共生のソフトでは、本体が動いているので、読者の設定とプラグインがそのまま効く。寄生ではほかのアプリの画面の中で編集でき、共生では Vim の窓に切り替えて編集する。
  - 擬態するソフトでは、再現された範囲の操作だけが通じる。
  - 近縁種では、一部のキーだけが通じる。
- 読者がソフトを探す入口は「どのアプリで Vim の操作を使いたいか」なので、ページは提供形態で分けたままにする。

## 採らなかった案

- 種別ごとにページを分ける：同じアプリ向けのソフトが別々のページに散らばり、使いたいアプリから探せなくなる。

## 結果

- Playgrounds のページから「not infected with vim」の節を消す。
- 項目の書式に、種別を書く欄が要る。
